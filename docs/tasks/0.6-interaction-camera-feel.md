# Task Brief - Interaction and Camera Feel 0.6

## Title

Implement Interaction and Camera Feel 0.6: focus, prompt and one-press activation

## Status

Implementation, build, automation, documentation and independent review corrections are complete on the active `codex/the-veil` working branch. A fresh 5 September 2026 build succeeded and all eighteen `TheVeil.*` tests passed. Subjective Editor/PIE feel checks remain human-owned.

## Player and production value

The accepted 0.5 movement shell needs one responsive action-adventure interaction loop before embodied contestants, social actions, Tribunal staging or night-operation spaces can be judged in play.

## Objective

When the player approaches a simple development object in `/Game/Maps/L_Dev_Sandbox`, the game can acquire a valid focus target, show a clear development prompt and activate it once per input press while rejecting blocked or out-of-range targets.

## Current behaviour

- `L_Dev_Sandbox` has the accepted 0.5 third-person shell.
- Keyboard and controller movement, look, sprint, crouch and jump are accepted by the Product Owner.
- Camera collision and movement feel are accepted for 0.5.
- There is no reusable interaction interface, focus trace, prompt state, test door or test object.

## Required behaviour

- Add a reusable native interaction interface and component.
- Trace from the camera-facing player context to find interactable targets.
- Validate range, line-of-sight and target-specific availability before focus or activation.
- Expose a development prompt for the focused target.
- Bind one-shot interaction for keyboard and controller without disturbing the accepted 0.5 input shell.
- Add simple development-only test door and inspectable or collectible object actors.
- Keep camera collision behaviour stable and expose bounded camera-feel defaults.
- Preserve all social-system information boundaries and avoid final-art production.

## Risks

- A focus trace can accidentally hit the player capsule or prompt through geometry.
- One-shot input can regress into repeated activation if bound to a triggered event.
- Prompt rendering can become throwaway UI that conflicts with the later conversation interface.
- Runtime test objects can be mistaken for final art if documentation is unclear; they are map-scoped development geometry only.
- Extending input without updating Blueprint assets can create a temporary Editor setup gap.

## Rollback

Revert this branch or the bounded interaction commit. No binary map or content files are expected from the native implementation. Rebuild and rerun the pre-existing automation suite to confirm the accepted 0.5 baseline is restored.
