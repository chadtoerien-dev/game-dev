# Task Brief — First Embodied Contestants 0.7a

## Objective

Place three visible, distinct development contestants in `L_Dev_Sandbox`, connect them to the existing state, memory and witness model, and give each a deterministic short patrol plus a typed contextual interaction response.

## In scope

- Native placeholder contestant character.
- Stable identities for Eleanor, Marcus and Beatrice.
- Contestant-state, memory and witness components.
- Runtime sandbox spawning without binary map edits.
- Bounded deterministic movement and development-only interaction copy.
- Automation for identity uniqueness, component ownership and interaction state.

## Non-goals

- Final models, animation, dialogue, voice, StateTrees or estate art.
- Full eight-contestant population.
- Social-action menus, Tribunal or night operations.
- `.umap`, World Partition or other binary-asset edits.

## Acceptance criteria

1. Three contestants spawn in `L_Dev_Sandbox` with stable, unique IDs.
2. Each owns contestant-state, memory and witness components.
3. Each is visibly distinct from the player placeholder and follows a bounded routine.
4. Focusing and interacting produces a typed development response.
5. Existing interaction, movement and social tests remain green.
6. Editor build and focused automation pass.

## Human checkpoint

Run PIE and confirm all three placeholders are present, move without obvious deadlock, show the correct name prompt and return distinct typed responses.
